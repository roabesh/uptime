# uptime — внешний пробник доступности

Проверяет снаружи, живы ли сервисы, и шлёт алерт в ntfy, если нет.

## Зачем это нужно

У каждого проекта есть свой сторож **на его же сервере**. Он видит почти всё:
упавший контейнер, кончившийся диск, отвалившуюся БД, сломанный DNS. Но у него
есть слепое пятно: **если сервер умирает целиком, сторож умирает вместе с ним**,
и наступившая тишина неотличима от «всё хорошо».

Этот пробник работает на инфраструктуре GitHub, поэтому переживает смерть любого
из серверов и способен об этом сообщить. Он не заменяет локальных сторожей, а
закрывает единственный сценарий, который им не виден.

## Что проверяется

| Проект | Адрес | Что означает провал |
|---|---|---|
| Major Radar | `major.yx8.ru/healthz` + `/readyz` | сервис недоступен / отвалилась БД |
| RunEvolution | `run.yx8.ru/health` | сервис недоступен |
| BillRazbil | `billrazbil.ru/` | сервис недоступен |

Раз в 10 минут, две попытки с паузой 30 секунд — одиночный сетевой сбой на
раннере GitHub не поднимает тревогу. Алерт каждого проекта уходит **в его
собственный ntfy-топик**, поэтому разделение подписок на телефоне сохраняется.

### Чего здесь нет и почему

**alinaroxbot** (профили alina и rita) не проверяется: это Telegram-бот без
веб-сервера, у него нет URL, который можно дёрнуть снаружи. Живость определяется
файлом-heartbeat на самом сервере, и это умеет только локальный healthcheck.
Косвенно бот всё же прикрыт: он живёт на одном VPS с Major Radar и RunEvolution,
поэтому смерть сервера будет видна по ним.

**daisydose** (`daisy.yx8.ru`) не добавлен: у него нет отдельного ntfy-топика.
Если понадобится — завести топик, положить секрет `NTFY_DAISYDOSE` и добавить
строку в матрицу.

## Секреты

Адрес ntfy-топика — фактически пароль: кто его знает, тот читает ваши алерты и
может слать поддельные. Поэтому топики хранятся **только в GitHub Secrets**
(Settings → Secrets and variables → Actions), а в коде — лишь имена секретов:

| Секрет | Проект |
|---|---|
| `NTFY_MAJOR_RADAR` | Major Radar |
| `NTFY_RUNEVOLUTION` | RunEvolution |
| `NTFY_BILLRAZBIL` | BillRazbil |

Секреты закрыты и в публичном репозитории: они не видны в логах, не передаются в
форки и недоступны в pull request'ах.

## Почему репозиторий публичный

У публичных репозиториев GitHub Actions **бесплатны без лимита**. У приватных
тарифицируется каждый прогон как целая минута, даже если он длится 10 секунд, —
платишь за количество запусков. 20.08.2026 квота аккаунта на этом кончилась,
задачи перестали стартовать, и мониторинг умер молча, оставив только письма о
падениях. Здесь этой проблемы нет.

Раскрывать тут нечего: кода проектов в репозитории не хранится, а домены и
health-эндпоинты публичны сами по себе — DNS отвечает кому угодно, а имена
доменов и так лежат в открытых Certificate Transparency логах.

## Проверить, что алерты дойдут

Не дожидаясь аварии: **Actions → uptime → Run workflow → `test_alert` = true**.
Во все три топика придёт сообщение с пометкой 🧪 ТЕСТ. Если секрет где-то не
задан — прогон упадёт с явной ошибкой, какого именно секрета не хватает.

## Устройство

```
.github/workflows/uptime.yml      проверки и алерты
.github/workflows/keepalive.yml   ежемесячный коммит-отметка
LAST-CHECK.txt                    отметка активности (содержимое не важно)
```

`keepalive` нужен из-за поведения GitHub: расписания отключаются после 60 дней
без коммитов в репозиторий, а прогоны активностью не считаются. Без него пробник
через два месяца выключил бы себя сам — и узнали бы об этом в худший момент.

Сторонние actions в проверках не используются, только `curl`: нечему стать
источником supply-chain атаки. Право записи есть лишь у `keepalive`, и только на
этот репозиторий.

## Добавить проект

Дописать блок в `matrix.include` файла `uptime.yml`:

```yaml
- name: Название
  url: https://example.com/health   # что дёргать
  ready: ""                         # необязательный второй эндпоинт (готовность БД)
  secret: NTFY_НАЗВАНИЕ             # имя секрета с адресом топика
```

Затем положить секрет с тем же именем в настройках репозитория.
